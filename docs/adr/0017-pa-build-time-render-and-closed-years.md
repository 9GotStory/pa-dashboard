# ADR-0017: PA render ตอน build แล้วดึง GAS สดต่อ และ PA ปีที่ปิดแล้วแช่แข็งไว้ใน repo

- สถานะ: ยอมรับ (D16) · 16 พ.ย. 2569 (grill 16 พ.ย. 2569) · แทนบรรทัด "PA และ `/sync` ยังเรียก GAS สด" ของ ADR-0006 เฉพาะส่วนของ PA และข้อ "ไม่แก้โค้ด PA" ของ ADR-0003 เฉพาะสองไฟล์ในข้อตัดสินใจ · [ADR-0019](0019-pa-takes-data-center-frame-and-colours.md) (23 พ.ย. 2569) เพิ่มข้อยกเว้นที่สาม: class ของสีและ transition ในไฟล์ component ของ PA
- เกี่ยวข้อง: ADR-0003, ADR-0006, ADR-0007, SPEC §2.11, §4, §6, §7, §9.6, SCHEMA §7, CODING_STANDARDS §1, GLOSSARY "PA", "snapshot", "PA ปีที่ปิดแล้ว"

## บริบท

PA เรียก GAS สดจากเบราว์เซอร์ทุกครั้งที่เปิดหน้า: `BATCH_ALL`, `hospitals` และ `tambon_master` พร้อมกัน แล้วจึงดึงแท็บ registry ตาม `meta.registry` วัดบนเว็บจริงเมื่อ 16 พ.ย. 2569 (Lighthouse 13.5.0 จำลองมือถือ ค่ากลางของ 3 รอบ) ได้ LCP ของ `/pa` 24.0 วินาที เทียบกับ 2.8 วินาทีของ `/` ราว 16.4 วินาที (68%) เป็นการรอ GAS และ `BATCH_ALL` ตัวเดียวใช้ราว 14 วินาที response ทั้งห้ารวมกันราว 365 KB ก่อนบีบอัด

ตัวเลขผลงานเปลี่ยนวันละครั้งตามรอบ sync ซึ่งสั่ง rebuild อยู่แล้ว (`system_logs` ตั้งแต่ 5 พ.ย. 2569: rebuild วันละ 1 ครั้งเกือบทุกวัน สูงสุด 4) ส่วนที่เปลี่ยนนอกรอบคือชีต registry (`kpi_master`, `kpi_epi`) และ `settings` ซึ่งตอนนี้ PA เห็นภายใน 60 วินาทีโดยไม่ต้อง rebuild ที่จำกัด 5 ครั้งต่อวัน

registry เป็นชีตเดียวไม่แยกปี เมื่อเปลี่ยนปีงบประมาณแล้วแก้ตัวชี้วัดหรือเป้าหมายของปีใหม่ ผลเทียบเป้าของปีก่อนจะหายไป แม้แถวดิบจะอยู่ในชีตปีย้อนหลัง (ADR-0007) ก็ตาม

## การตัดสินใจ

- prebuild GET response ของ GAS ทั้งห้าแบบไม่แปลงเป็นไฟล์ snapshot ของ PA ดึงไม่ได้หรือโครงไม่ครบให้ build ล้ม (กติกาเดียวกับ ADR-0006)
- การประมวลผลของ PA เป็นฟังก์ชันล้วนตัวเดียว ใช้ทั้งตอน build กับไฟล์ snapshot และในเบราว์เซอร์กับ response สด จึงไม่มีสูตรสองชุด
- HTML ของ `/pa` มีตัวเลขของ build ล่าสุด (รวมแถวดิบที่ modal ใช้) แล้ว hook ดึง GAS สดในพื้นหลังและแทนที่เมื่อได้มา GAS ล้มก็แสดงข้อมูลของ build ต่อโดยไม่แสดง error · เลิกใช้ localStorage `PA_DASHBOARD_CACHE_V4` · `?cat=` อ่านหลัง hydrate
- ไฟล์ PA ที่แก้ได้มีแค่ `src/app/pa/page.tsx` และ `src/lib/useKPIData.ts` component ของ PA, `types.ts` และ `kpi-utils.ts` ยังห้ามแก้ · GAS ไม่แก้ · เนื้อหาเดิมของ `page.tsx` ที่ย้ายไปไฟล์ใหม่ใน `src/app/pa/` นับเป็นส่วนของ `page.tsx` เพราะหน้าที่อ่านไฟล์ตอน build ต้องเป็น server component ที่ส่ง props ให้ส่วน client (เพิ่มตอน F80)
- **PA ปีที่ปิดแล้ว:** ก่อนเปลี่ยน `current_year` (ตั้ง `current_quarter = 4` และ sync ปีเดิมครั้งสุดท้ายก่อน) เก็บ snapshot ของ PA ของปีนั้นเป็นไฟล์ถาวรใน repo นอก `public/data/` แล้ว build หน้า `/pa/{ปี}` จากไฟล์นี้ ไม่ดึง GAS สด · เริ่มที่ปี 2569

## ทางเลือกที่ไม่เลือก

- **เปลี่ยนแค่แหล่งข้อมูล (fetch ไฟล์ snapshot แทน GAS):** แก้ไฟล์เดียว แต่ยังรอ JS ราว 5.8 วินาทีและ render ราว 1.8 วินาที ประเมิน LCP ราว 8 วินาที ไม่ถึงความเร็วของ Data Center
- **render ตอน build อย่างเดียว:** เร็วเท่ากัน แต่การแก้ registry ต้องรอ rebuild ซึ่งจำกัด 5 ครั้งต่อวัน
- **คำนวณปีที่ปิดแล้วใหม่จากชีต** (`BATCH_ALL` ตามปีกับสำเนา registry รายปี): ตาม HDC ที่ปรับข้อมูลภายหลังได้ แต่ต้องแก้ `รหัส.js` เพิ่มชีต และหน้าปีที่ปิดแล้วกลับไปพึ่ง GAS · ผลงานของปีที่ปิดแล้วควรคงตามที่ใช้ประเมิน
- **สร้างปี 2565–2568 ย้อนหลัง:** ไม่มี registry ของปีเหล่านั้นแล้ว เป้าหมายและรายการตัวชี้วัดจะไม่ตรงกับที่ใช้จริง

## ผลที่ตามมา

- GAS ยังถูกเรียกทุกครั้งที่เปิด `/pa` เหมือนเดิม แต่ผู้ชมไม่ต้องรอ และ `/pa` อยู่ได้แม้ GAS ล่ม
- ตัวเลขบนหน้าอาจเปลี่ยนหลังเปิดราว 16 วินาที เมื่อข้อมูลสดต่างจาก build (เหมือนพฤติกรรมของ cache เดิม)
- ลิงก์ `?cat=` เห็นแท็บ "ทั้งหมด" แวบหนึ่งก่อนสลับ
- repo มีไฟล์ข้อมูลที่ commit ได้เป็นครั้งแรก ราว 365 KB ต่อปีที่ปิด · HDC ปรับข้อมูลของปีที่ปิดแล้วภายหลังจะไม่ขึ้นบนหน้านั้น
- ขั้นเปลี่ยนปีงบประมาณมีขั้นแช่แข็งเพิ่ม ถ้าข้ามไป registry ของปีนั้นจะหายและสร้างคืนไม่ได้

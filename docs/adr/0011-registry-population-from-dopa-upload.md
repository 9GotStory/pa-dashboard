# ADR-0011: ประชากรบนหน้าแรกมาจากยอดทะเบียนราษฎร ณ 31 ธ.ค. ของกรมการปกครองที่ผู้ดูแลอัปโหลดปีละครั้ง ไม่ใช่จาก HDC

- สถานะ: ยอมรับ · 6 พ.ย. 2569 (D10) · ADR-0014 แก้ข้อ "ต่อปีใช้สองไฟล์": ใช้ `stat_m` แทน `stat_t`
- เกี่ยวข้อง: SPEC §2.2, §2.3, §9.1, §9.2, §12.1, §12.4, SCHEMA §2.6–2.7, §3.8–3.9, §11, GLOSSARY หมวด "ประชากร", ADR-0005

## บริบท

หน้าแรกตาม R6 มีสรุปประชากร แผงพื้นที่ที่เลือก และตารางประชากรรายตำบล (คอลัมน์ ชาย หญิง รวม และ "ครัวเรือน" ตามคำของ R6) ซึ่งเฟส 1 ซ่อนไว้ ผู้ใช้คาดหวังประชากรทะเบียนราษฎรและพีระมิดประชากร ข้อมูลที่ตรวจเมื่อ 6 พ.ย. 2569:

- หัวข้อ "ประชากร" ของ HDC: ตารางที่ `report_data` ส่งมาครบคือ `s_pop_sex_age` เป็นจำนวนคนตาม TYPEAREA 1 และ 3 หลังตัดความซ้ำซ้อน อำเภอสองได้ 34,114 คน คนละนิยามกับทะเบียนราษฎร
- ทะเบียนราษฎรใน HDC (`s_pop_sex_age_moph`, `s_midyearpopmoph`, `s_pop_dopa_hdc`): `report_data` ตอบ 0 แถวสำหรับจังหวัด 54 ทุกปีที่ลอง (2567–2569) ส่วนหน้าเว็บ HDC แสดงได้แค่ระดับอำเภอ (46,362 คน ประมวลผล 1 เม.ย. 2569)
- กรมการปกครองประกาศจำนวนราษฎรตามหลักฐานการทะเบียนราษฎร ณ 31 ธ.ค. ปีละครั้ง ของปี 2568 ประกาศราว 25 มี.ค. 2569 ([ประชาชาติ](https://www.prachachat.net/general/news-1984243), [Policy Watch](https://policywatch.thaipbs.or.th/article/economy-267))
- stat.bora มีไฟล์ของยอดนี้ให้ดาวน์โหลด ไม่มี header CORS:
  - `stat_t{yy}.txt` ทั้งประเทศ ระดับตำบล มีชาย หญิง รวม และบ้าน ปี 2568 อำเภอสองได้ 46,527 คน 20,101 บ้าน ไฟล์แก้ไขล่าสุด 24 มี.ค. 2569
  - `{yy}12cc54.txt` จังหวัดแพร่ ระดับตำบล มีจำนวนรายปีอายุ 0 ถึงมากกว่า 100 ปี แยกเพศ แต่ระบุตำบลด้วยชื่อเท่านั้น ชื่อตำบลซ้ำกันข้ามอำเภอได้
- stat.bora มีข้อมูลรายเดือนด้วย ได้แก่ไฟล์ `3_{yymm}.xls` (ตาราง HTML ทั้งประเทศ ระดับตำบล มีถึง ต.ค. 2569) และ API ภายในของแอปรายเดือน (`connectSAPI/stat_forward.php`) ซึ่งไม่มีเอกสาร
- ไฟล์ของ ธ.ค. 2568 ทั้งสามไฟล์ (`stat_t68`, `6812cc54`, `3_6812`) ตรงกันทุกตัวเลขในทั้ง 10 แถวของอำเภอสอง
- แถวของสำนักทะเบียนอำเภอสอง (`5406`) ไม่รวมเขตเทศบาลตำบลสอง ซึ่งแยกเป็นสำนักทะเบียน `5489` คลุมบางส่วนของบ้านหนุนและบ้านกลาง ต้องรวมตามตำบล
- จำนวนรายปีอายุของอำเภอสองรวมได้ 46,362 คน น้อยกว่ายอดรวม 165 คน เท่ากับผู้ไม่ใช่สัญชาติไทย 81, ผู้มีชื่อในทะเบียนบ้านกลาง 75 และผู้อยู่ระหว่างการย้าย 9 และเท่ากับตัวเลขของ HDC พอดี

## การตัดสินใจ

- ใช้เฉพาะยอด ณ 31 ธ.ค. ไม่ใช้ยอดรายเดือน
- ประชากรทุกส่วนของหน้าแรก (ช่องสรุป แผงพื้นที่ ตารางรายตำบล พีระมิด) ใช้ประชากรทะเบียนราษฎรนิยามเดียว ยอดรวมใช้ยอดรวมทั้งหมดของ `stat_t` ซึ่งเป็นตัวเลขที่ประกาศ
- แสดง "บ้าน" ตามกรมการปกครอง แทน "ครัวเรือน" ของ R6
- ต่อปีใช้สองไฟล์: `stat_t{yy}.txt` สำหรับประชากรและบ้าน และ `{yy}12cc54.txt` สำหรับอายุ ผู้ดูแลดาวน์โหลดจาก stat.bora แล้วอัปโหลดผ่านส่วนใหม่ในหน้า `/sync` (PIN เดิม)
- เบราว์เซอร์เก็บเฉพาะแถวระดับตำบลของ `district_code` ตรวจกับแถวยอดรวมของแต่ละสำนักทะเบียน และเมื่อมีทั้งสองไฟล์ของปีเดียวกัน ยอดรวมรายตำบลต้องตรงกัน ไม่ตรงให้ปฏิเสธ การตรวจข้อหลังกันการจับคู่ตำบลผิดจากชื่อใน `cc54`
- GAS เก็บแถวดิบของอำเภอ รวมแถวของเทศบาล ใน PA-Data สองชีตที่คอลัมน์ตรงกับไฟล์ต้นทาง: `registry_population` (จาก `stat_t`) และ `registry_population_age` (จาก `cc54`) เก็บแบบนี้เพื่อให้ตรวจย้อนกับ stat.bora ได้ทีละแถว แยกตาม `yymm` (เดือน 12 เสมอ) อัปโหลดปีเดิมซ้ำแทนที่ของเดิม เก็บทุกปี เริ่มจากย้อนหลัง 2564–2568 การรวมเป็นรายตำบลและเป็นช่วงอายุทำตอน build
- action ใหม่ของ GAS เขียนได้เฉพาะสองชีตนี้ ไม่รับชื่อชีตจากคำขอ
- ยังไม่มีข้อมูล → หน้าแรกซ่อนส่วนประชากรแบบเฟส 1 ไม่ทำให้ build ล้ม
- ไม่ใช้ประชากรของ HDC บนหน้าแรก

## ทางเลือกที่ไม่เลือก

- `s_pop_sex_age` ของ HDC: ครบและดึงอัตโนมัติได้ แต่เป็นคนละนิยาม ตัวเลขต่ำกว่าทะเบียนราษฎรราว 12,000 คน
- `s_person_pyramid` ของ HDC: ตัวเลขชุดเดียวกับ `s_pop_sex_age` แต่ทั้งจังหวัดมี 13,971 แถว เกิน `limit` 5,000
- ช่องสรุปใช้ทะเบียนราษฎร แต่ตารางใช้ TYPEAREA: ยอดรวมของตารางจะไม่เท่ากับช่องสรุป
- CSV ที่ export จากหน้าเว็บ HDC: มีแค่ระดับอำเภอ
- data.go.th `dopa-star`: ใบรับรอง TLS ของ `catalog.dopa.go.th` ตรวจไม่ผ่าน และล่าสุดเป็นปี 2567 · `pr02` ของสำนักงานจังหวัดแพร่: มีแค่ระดับอำเภอ
- ข้อมูลรายเดือน ทั้งไฟล์ `3_{yymm}.xls` และ API: ตัวเลขเปลี่ยนทุกเดือน จึงไม่ตรงกับยอดที่ประกาศ และส่วนต่าง ๆ ของหน้าจะตัดยอดคนละวัน อีกทั้ง API ไม่มีเอกสารและไม่มี CORS
- `3_{yy}12.xls` สำหรับอายุ: ตัวเลขเท่ากับ `cc54` และมีรหัสตำบล แต่ไฟล์ใหญ่ 45.8 MB เทียบกับ 76 KB
- ให้ prebuild ดึงจาก stat.bora เอง: ทุก build จะพึ่งเว็บภายนอก
- เก็บตัวเลขเป็นไฟล์ใน repo แล้วแก้ผ่าน PR: คนที่อัปเดตเป็นเจ้าหน้าที่ที่ไม่ได้ใช้ git

## ผลที่ตามมา

- เป็นแหล่งข้อมูลแรกที่ไม่ใช่ HDC: ข้อความใน SPEC §9.1 ที่ว่า "ทุกตัวเลขมาจาก HDC" ต้องแก้ และส่วน "ที่มาของข้อมูล" ต้องระบุกรมการปกครอง
- ต้องมีคนอัปโหลดปีละครั้งหลังประกาศ (ราวปลาย มี.ค.) ช่วง ม.ค.–มี.ค. หน้าเว็บยังแสดงยอดของปีก่อน
- ปีของข้อมูลเป็นปีปฏิทิน ไม่ใช่ปีงบประมาณ หน้าเว็บจึงเขียนกำกับว่า "ณ 31 ธ.ค. {ปี}"
- ยอดของพีระมิดน้อยกว่ายอดรวมเท่ากับประชากรที่ไม่แยกอายุ (ปี 2568 คือ 165 คน) หน้าเว็บต้องเขียนกำกับไว้
- POST ที่เพิ่มเข้ามาไม่มีการยืนยันตัวตนฝั่ง server เช่นเดียวกับ `save_kpi_data` (ADR-0005)
- `src/app/sync/page.tsx` อยู่ในรายการไฟล์ห้ามแก้ จึงต้องเพิ่มจุดนี้ใน SPEC §12.1

# ADR-0015: หน้ารายงาน `/reports/{id}` เปลี่ยนแบบอ้างอิงจาก R6 เป็น V0.4.2 และแต่ละตารางต้นทางมีหน้าของตัวเอง

- สถานะ: ยอมรับ · 12 พ.ย. 2569
- เกี่ยวข้อง: SPEC §2.7, §5.2, §9.1, §9.4, §9.5, §9.6, D14, SCHEMA §4.4, §4.6, GLOSSARY "V0.4.2", "R6", "การวิเคราะห์ตาราง", "รายงานที่รอวิเคราะห์", "ยืนยันแล้ว / อนุมาน", "ด้าน", ADR-0008, ADR-0009, ADR-0012, ADR-0013

## บริบท

ADR-0012 และ ADR-0013 เปลี่ยนสี กรอบหน้า และ `/reports` แล้ว แต่ `/reports/{id}` ยังใช้โครงหน้าของ R6 รอแบบของตัวเอง Product Owner ทำแบบนั้นแล้วคือ V0.4.2 (`docs/reference/report-detail-v0-4-2/`) มีสามหน้า: ANC V0.2 (ตรวจรับแล้ว) สำหรับตัวชี้วัดเดียว · EPI1 ตารางภาพรวมวัคซีน 20 รายการที่เปิดดูรายละเอียดทีละรายการ · AGED9 ความครอบคลุมตามด้วยผลการคัดกรอง 9 ด้านที่เปิดดูรายตำบลได้

หน้าปัจจุบันเป็น `CoverageReport` ตัวเดียวสำหรับ 18 ตารางต้นทาง (21 รายงาน) ที่เลือกวิธีแสดงจากกลุ่มคอลัมน์ใน header (SCHEMA §4.1–4.3) การวิเคราะห์ตารางของ F48 (SCHEMA §4.6) พบว่าหน้าเดียวแบบนี้แสดงข้อมูลผิดหรือแสดงไม่ได้:

- HDC เก็บศูนย์เป็นช่องว่าง (SCHEMA §4.6.1) วัคซีน 10 รายการใหม่ของ `s_epi1` ปี 2565–2568 จึงขึ้นเป็น 0% และไม่ผ่านเกณฑ์ ทั้งที่ปีนั้นไม่ได้เก็บรายการนี้ · `pcv4` ของ `s_epi2` ว่างทุกปีแต่อยู่ในตัวเลือก · ไตรมาสของ `s_kpi_food` ว่างทุกปีแต่มีให้เลือก
- PCV ไม่อยู่ใน `kpi_epi` โดยตั้งใจ แต่หน้าใช้ `goal` ของรายงานแทน PCV จึงขึ้นว่าไม่ผ่านเกณฑ์ที่ไม่มีใครตั้ง
- ตาราง 1 แถวต่อหน่วยบริการ (`s_kpi_childdev4`, `s_kpi_childdev2`, `s_ncd_screen_repleate1`, `s_ht_screen_follow`) มี `areacode` เป็นที่ตั้งหน่วย กราฟรายตำบลจึงเป็นแค่ที่ตั้งของหน่วยบริการ ไม่ใช่ผลของคนในตำบล
- ข้อมูลเฉพาะตารางไม่มีที่แสดง: นมแม่ตามเดือนอายุ (`r1`–`r6`) วิธีวัด HBPM/OBPM กรวยฟันดีไม่มีผุ (`c` → `b` → `a`) และ 9 ด้านของผู้สูงอายุ

V0.4.2 ทำจากข้อมูลที่อ่านจาก PA-Data ตอนทำต้นแบบ ไม่ได้ทดสอบกับ Next.js และต่างจากระบบหลายจุด:

- เมนูมี 5 ลิงก์ รวม anchor ชี้เข้าหน้าแรก และเมนูแฮมเบอร์เกอร์บนมือถือ ซึ่งขัดกับ D11
- มีแถบ "DESIGN REVIEW" บนสุด และกล่อง "แหล่งข้อมูลและข้อจำกัดของต้นแบบ"
- สีเป็น hex ดิบ เช่น `#198467` ซึ่ง `dc-brand-accent` ของเราปรับให้เข้มกว่าเพื่อผ่าน WCAG AA (SPEC §9.1)
- ผ่าน/ไม่ผ่านของ EPI1 เป็นผลประเมินเบื้องต้นตามเกณฑ์ของต้นแบบ และ PCV แสดง "รอตรวจสอบ"
- ชื่อไฟล์ CSV ไม่มีรหัสรายงาน ซึ่งต้องมีเพราะตารางเดียวมีหลายรายงานได้ (SPEC §9.4)

## การตัดสินใจ

- V0.4.2 เป็นแบบอ้างอิงด้านหน้าตาและการใช้งานของ `/reports/{id}` แทน R6 · SPEC §9.4 เป็นสัญญา เมื่อขัดกับ V0.4.2 ให้ถือ SPEC · ทุกตัวเลขมาจาก snapshot ไม่ใช้ตัวเลขของต้นแบบ
- **แต่ละตารางต้นทางมีหน้าของตัวเอง** ที่ออกแบบจากการวิเคราะห์ตาราง ตารางที่รูปเดียวกันใช้หน้าเดียวกันได้ (เช่น `s_kpi_anc12` กับ `s_anc5`) หน้าหนึ่งมีสองชั้น:
  - **ชั้นข้อมูล:** ฟังก์ชันเดียวที่รับ snapshot ของรายงานกับตัวกรอง แล้วคืนค่าทุกตัวที่หน้านั้นใช้ ไม่ import React ไม่แตะ DOM มีเทสต์กับ fixture ที่ตัดจาก snapshot จริง ค่าคาดหวังจาก SCHEMA §4.6 · `values.ts` ยังเป็นตัวคำนวณ (กลุ่มคอลัมน์ ผลรวม ร้อยละ เกณฑ์) ชั้นข้อมูลเรียกใช้ ไม่เขียนสูตรซ้ำ
  - **ชั้นแสดงผล:** จัดวางชิ้นส่วนร่วม ไม่คำนวณเอง
- **ชิ้นส่วนร่วม** แยกออกจาก `CoverageReport` ก่อน (F51): โหลด snapshot ตัวกรองและ URL ตัวเลขสรุป กราฟ ตาราง CSV และพิมพ์ ส่วนเปิดดูรายละเอียด และสถานะไม่มีข้อมูล กติกาที่ทุกหน้าต้องเหมือนกัน (CSV กันสูตร ช่องว่างแทนศูนย์ "—") จึงมีที่เดียว
- **ตัวเลือกหน้า** อยู่ฝั่ง client เลือกหน้าตามตารางต้นทางด้วย `next/dynamic` แต่ละรายงานจึงโหลดแค่ chunk ของตารางตัวเอง · ตัวเลือกต้องเป็น Client Component เพราะเอกสาร Next.js ระบุว่า Server Component ที่ import Client Component แบบ dynamic ยังไม่แยก chunk ให้ (`node_modules/next/dist/docs/01-app/02-guides/lazy-loading.md`)
- `s_epi_complete` ใช้หน้าเดียวสำหรับ 4 รายงาน (อายุ 1, 2, 3, 5 ปี) ข้อความต่างกันตาม `catalog.json`
- **opt-in ของ ADR-0008 ไม่พอให้รายงานขึ้นเว็บอีกต่อไป:** รายงานที่ใช้งานต้องมีตารางต้นทางที่ผ่านการวิเคราะห์ตารางและมีหน้าของตาราง · รายงานที่รอวิเคราะห์ไม่อยู่ใน `/reports` ไม่มีหน้า `/reports/{id}` ไม่อยู่ในรายงานที่เกี่ยวข้องและลิงก์บนหน้าแรก และ build กับ `dc:check` เตือนชื่อรายงานและตารางต้นทาง (เตือน ไม่ล้ม) · ผู้ดูแลยังเปิดรายงานใหม่ในชีตได้ แต่รายงานนั้นขึ้นเว็บเมื่อตารางมีหน้าแล้ว
- **expand–contract:** ระหว่าง Track ตารางที่ยังไม่มีหน้าใช้ `CoverageReport` ต่อ ไม่มีรายงานหายจากเว็บ · F62 ลบ `CoverageReport` เมื่อทุกตารางมีหน้า แล้วจึงเปิดกติการายงานที่รอวิเคราะห์
- **กติกาข้อมูลที่ทุกหน้าใช้ (SPEC §9.4):**
  - รายการหรือช่วงเวลาที่ผลงานรวมทั้งอำเภอเป็น 0 ทั้งปี = ไม่มีข้อมูลรายการนั้นปีนั้น แสดง "—" ไม่ใช่ 0% หรือไม่ผ่าน และไม่ลงจุดในแนวโน้ม · รายการที่ว่างทุกปีไม่อยู่ในรายการ · ระดับช่วงเวลาที่คอลัมน์ว่างทั้งปีไม่มีให้เลือก
  - เกณฑ์ของตารางหลายรายการมาจาก `measure_goals` อย่างเดียว ไม่มี → "ไม่มีเกณฑ์" ไม่มีป้ายผ่านหรือไม่ผ่าน ไม่ถอยไปใช้ `goal` ของรายงาน · ไม่ใช้ป้าย "รอตรวจสอบ" ของต้นแบบ
  - ตาราง 1 แถวต่อหน่วยบริการเปรียบเทียบตามหน่วยบริการอย่างเดียว ไม่มีตัวกรองตำบลและกราฟรายตำบล
  - คอลัมน์ที่อนุมานไม่แสดงเป็นอัตราและไม่ตีความทางคลินิก
  - ร้อยละของ `s_ncd_screen_repleate1` และ `s_ht_screen_follow` คือ `result` ÷ `target` ตาม SCHEMA §4.3 เหมือนตารางอื่น ไม่ใช่ `result_13` ÷ `target_13` ที่กราฟบนหน้า HDC ใช้ ข้อจำกัดของหน้าบอกความต่างนี้ (ตัดสินใน F49 12 พ.ย. 2569)
- คงเมนู 3 ลิงก์ของ D11 · ตัดแถบ DESIGN REVIEW และกล่องข้อมูลต้นแบบ · สีใช้ token ของระบบ ไม่ใช้ hex ของต้นแบบ ไม่เพิ่ม token · ขั้นหดของ ADR-0012 (ลบชื่อสีของ R6) ที่ ADR-0013 เลื่อนไว้ ทำใน Track นี้ (F63)

## ทางเลือกที่ไม่เลือก

- **รูปแบบหน้าแบบตั้งค่า** (หน้าไม่กี่แบบที่ตั้งค่าต่อตาราง): ข้อมูลเฉพาะตาราง เช่น นมแม่ตามเดือนอายุ วิธีวัด HBPM/OBPM และกรวยฟันผุ ไม่เข้ากับแบบใด ต้องเพิ่มตัวเลือกจนการตั้งค่าซับซ้อนกว่าเขียนหน้า
- **หน้าเขียนเองทั้งหมดต่อตาราง** ไม่มีชิ้นส่วนร่วม: CSV กันสูตร ช่องว่างแทนศูนย์ และส่วนเปิดดูรายละเอียดถูกคัดลอก 18 ชุด แก้ข้อเดียวต้องแก้ทุกหน้า
- **ตรวจรูปแบบจาก header อย่างเดียว** (แบบ `CoverageReport`): header บอกไม่ได้ว่าคอลัมน์ว่างทั้งปี ตารางเป็น 1 แถวต่อหน่วยบริการ หรือคอลัมน์หมายถึงอะไร ซึ่งเป็นที่มาของปัญหาในบริบท
- **ร้อยละแบบ `_13` ของ HDC สำหรับตารางติดตามยืนยันวินิจฉัย:** คอลัมน์ `_13` ว่างปี 2565–2567 (`s_ncd_screen_repleate1`) และ 2565–2566 (`s_ht_screen_follow`) แนวโน้ม 5 ปีจะขาดหลายปี และกติกาต่างจากตารางอื่น
- **ให้รายการที่ไม่มีใน `measure_goals` ใช้ `goal` ของรายงานต่อ:** PCV จะขึ้นว่าไม่ผ่านเกณฑ์ที่ `kpi_epi` ตั้งใจไม่มี

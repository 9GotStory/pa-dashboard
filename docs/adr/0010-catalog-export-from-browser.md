# ADR-0010: แค็ตตาล็อก HDC ดึงจากเบราว์เซอร์ของผู้ดูแลเป็นไฟล์ export ไม่ใช่จากสคริปต์

- สถานะ: ยอมรับ · 30 ต.ค. 2569 (D9)
- เกี่ยวข้อง: SPEC §5.3, §12.3, SCHEMA §5, §5.5

## บริบท

API แค็ตตาล็อก (`/opendata_api/reports/categories` และ `.../categorie/by-category-id/{cat_id}`) ตอบ 403 ให้ไคลเอนต์ที่ไม่ใช่เบราว์เซอร์ ทดสอบ 30 ต.ค. 2569 จากเครื่องผู้ดูแล: เบราว์เซอร์ได้ข้อมูล, `curl` และ `fetch` ของ node ได้ 403 ขณะที่ `POST /api/report_data` จาก `curl` ได้ 201 ตามปกติ แผนเดิมให้ `hdc-catalog.js` (node) เรียก API นี้เอง

## การตัดสินใจ

- ผู้ดูแลรัน snippet `tools/hdc-catalog-export.js` ใน DevTools console บนหน้า opendata.moph.go.th ซึ่งดึงทุกหัวข้อแล้วดาวน์โหลดเป็นไฟล์ export แค็ตตาล็อกไฟล์เดียว (SCHEMA §5.5)
- `hdc-catalog.js find/refresh` อ่านไฟล์นั้นผ่าน `--from` ไม่เรียก MOPH
- สคริปต์ของโปรเจกต์ห้ามปลอม `User-Agent` หรือ header อื่นให้ดูเป็นเบราว์เซอร์ แม้จะทำให้ผ่านก็ตาม

## ทางเลือกที่ไม่เลือก

- ให้ node ส่ง header แบบเบราว์เซอร์: ตัดทิ้งโดยหลักการ ไม่หลบการกันของผู้ให้บริการ
- ให้ GAS (`UrlFetchApp`) ดึงแทน: GAS ดึง `report_data` จาก MOPH ได้ไม่เสถียรอยู่แล้ว (SPEC §3) และน่าจะโดน 403 เช่นกัน
- ปุ่มรีเฟรชบนหน้า `/sync`: ใช้ได้ แต่ต้องเขียน UI เพิ่มในเฟส 1 คงไว้เป็นงานเฟส 2

## ผลที่ตามมา

- รีเฟรชแค็ตตาล็อกเป็นงานที่ต้องมีคนเปิดเบราว์เซอร์ ทำเป็นครั้งคราว (ตอน seed และเมื่ออยากเพิ่มหัวข้อ) ไม่ใช่งานอัตโนมัติ
- ไฟล์ export เป็น snapshot ณ วันรัน รายงานที่ HDC เพิ่มหลังจากนั้นจะปรากฏเมื่อ export ใหม่
- `find` ทำงาน offline ได้จากไฟล์

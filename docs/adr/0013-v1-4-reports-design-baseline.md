# ADR-0013: หน้ารายงานสุขภาพ `/reports` เปลี่ยนแบบอ้างอิงจาก R6 เป็น V1.4

- สถานะ: ยอมรับ · 11 พ.ย. 2569 · ADR-0015 ออกแบบ `/reports/{id}` ใหม่ตาม V0.4.2 และทำขั้นหดของ token ในรอบนั้น
- เกี่ยวข้อง: SPEC §2.5, §9.1, §9.3, §9.6, D12, SCHEMA §9 `LibraryQuery` และ `LibraryList`, GLOSSARY "รายงานสุขภาพ", "V1.4", "R6", ADR-0008, ADR-0012

## บริบท

ADR-0012 เปลี่ยนสีและกรอบหน้าทั้งเว็บตาม V7.6 แต่ `/reports` ยังใช้โครงหน้าของ R6 รอแบบรอบถัดไป Product Owner ทำแบบนั้นแล้วคือ V1.4 (`docs/reference/reports-v1-4/`) ซึ่งเปลี่ยนชื่อหน้าเป็น "รายงานสุขภาพ" เพิ่ม Hero ขนาดเล็ก และเปลี่ยนตารางแบ่งหน้าของ R6 เป็นรายการลิงก์ต่อกันตามหมวด หัวข้อ และกลุ่ม

V1.4 ทำจาก fixture ของแค็ตตาล็อก ณ 4 พ.ย. 2569 และไม่ได้ทดสอบกับ Next.js จึงต่างจากระบบหลายจุด:

- เมนูมี 5 ลิงก์ รวม anchor ชี้เข้าหน้าแรก และใช้เมนูแฮมเบอร์เกอร์บนมือถือ ซึ่งขัดกับ D11
- แถวรายงานไม่มีปีล่าสุดที่มีข้อมูล ระบบจึงไม่บอกว่ารายงานที่เพิ่งเปิดใช้ยังไม่มีข้อมูล
- สีในแบบเป็น hex ดิบหลายค่า และมีป้ายภาษาอังกฤษเหนือชื่อหน้า
- ต้นแบบมีแถวรายงานใน HTML ตั้งแต่ก่อน JS โหลด แต่ static export ไม่รู้ query ของ URL ตอน build

## การตัดสินใจ

- V1.4 เป็นแบบอ้างอิงด้านหน้าตาและการใช้งานของ `/reports` แทน R6 · SPEC §9.3 เป็นสัญญา เมื่อขัดกับ V1.4 ให้ถือ SPEC · `/reports/{id}` ยังตาม R6 ไม่เปลี่ยนเนื้อหา (ภายหลังเปลี่ยนเป็น V0.4.2 ตาม ADR-0015)
- ชื่อหน้าเป็น "รายงานสุขภาพ" ทุกที่ที่ผู้ใช้เห็น รวม breadcrumb ของ `/reports/{id}` และข้อความบนหน้าแรก
- ไม่แบ่งหน้า แสดงทุกรายงานที่ตรงต่อกัน · `page` และ `size` ออกจาก `LibraryQuery` ลิงก์เก่าที่มีสองค่านี้ยังใช้ได้โดยไม่สนใจค่าเหล่านี้ · ไม่ตั้งเกณฑ์จำนวนรายงาน เพราะแค็ตตาล็อกเป็น opt-in (ADR-0008) รายงานเพิ่มเมื่อผู้ดูแลเปิดเองเท่านั้น
- แถวรายงานมีแค่ชื่อกับลูกศร ไม่มีปีล่าสุดและ `source_table` · มีข้อความรองเมื่อ HDC ไม่แสดงรายงานนั้นแล้ว หรือเมื่อรายงานยังไม่มีข้อมูล
- HTML ที่ build ออกมามีลิงก์ของทุกรายงาน แล้ว client กรองตาม URL หลังโหลด ลิงก์ที่มีตัวกรองจึงเห็นรายการเต็มแวบหนึ่ง
- คงเมนู 3 ลิงก์ของ D11 · ไม่มีป้ายภาษาอังกฤษใน Hero · สีใช้ token ของ V7.6 ที่มีอยู่ ไม่เพิ่ม token
- ไฟล์ของ `/reports` ย้ายไปใช้ token ชื่อใหม่ แต่ชื่อเก่าของ R6 ยังอยู่จนกว่าจะออกแบบ `/reports/{id}` ใหม่ เพราะหน้านั้นยังใช้อยู่ (ขั้นหดของ ADR-0012 จึงเลื่อนไปรอบนั้น)

## ทางเลือกที่ไม่เลือก

- คงการแบ่งหน้า 10/20 ของ R6: รายงานที่ใช้งานมีราว 20 รายการ แบ่งหน้าแล้วต้องกดเปลี่ยนหน้าเพื่อดูรายการสั้น ๆ
- ตัดปีล่าสุดโดยไม่มีอะไรแทน: ผู้ใช้จะเปิดรายงานที่ยังไม่มีข้อมูลโดยไม่รู้ล่วงหน้า
- HTML มีแค่ข้อความ "กำลังโหลด" แบบเดิม: ไม่มีเนื้อหาจนกว่า JS จะโหลด ซึ่งขัดกับ V1.4
- เปลี่ยนเมนูเป็น 5 ลิงก์ตาม V1.4: ต้องกลับ D11 ซึ่งตัดสินไว้ไม่ถึงสัปดาห์ และหน้าแรกก็ไม่ได้ใช้

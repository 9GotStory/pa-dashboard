# ADR-0005: ไม่มีการยืนยันตัวตนฝั่ง server ในเฟส 1

- สถานะ: ยอมรับ · 29 ต.ค. 2569 (D5)
- เกี่ยวข้อง: SPEC §8, §14

## บริบท

`doPost` ของ GAS ไม่ตรวจสิทธิ์ PIN ของหน้า `/sync` ตรวจฝั่ง client และ `DIAG_PIN` อยู่ใน repo สาธารณะ เคยร่าง token ใน Script Properties + Cloudflare Access แล้วพบว่าเพิ่มภาระดูแล (ความลับหลายค่า, env, หน้า login ใหม่) เกินความเสี่ยงที่ลดได้

## การตัดสินใจ

ยอมรับความเสี่ยงในเฟส 1 ไม่เพิ่มการยืนยันตัวตน เพราะ (1) เป็นสถานะเดิมของระบบ (2) ทุกตารางดึงจาก MOPH ใหม่ได้ทันที และ trigger รายวันเขียนปีปัจจุบันทับกลับเอง (3) ไม่มีข้อมูลส่วนบุคคลในชีต (4) `rebuild` จำกัด 5 ครั้ง/วัน

## ผลที่ตามมา

- การทำลายข้อมูลที่เลวร้ายสุดแก้ได้ด้วย `sync-moph-to-gas.js --backfill --force`
- `syncAllData` ส่ง `force: true` ทุกครั้ง เพื่อให้ trigger รายวันเขียนทับแถวแปลกปลอมที่ `date_com` เป็นอนาคตได้เอง ไม่อย่างนั้นจะติด `Stale data` (ADR-0007) จนกว่าจะมีคนรัน `--force` (เพิ่ม 30 ต.ค. 2569)
- `setup=dc_seed` (F08) เขียนคอลัมน์ admin ของรายงาน seed 21 รายการทับ ใครที่มี `DIAG_PIN` จึงล้างค่าที่ admin แก้ทีหลังได้ แก้คืนได้ในชีต `hdc_reports` (เพิ่ม 30 ต.ค. 2569)
- ทบทวนใหม่เมื่อเริ่มมีข้อมูลที่ไม่ใช่สาธารณะ หรือมีโดเมนเองที่ใช้ Cloudflare Access ได้
